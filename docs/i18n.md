# Localisation (P5)

Decision, in five lines:

1. **Library: i18next + react-i18next.** Works with TanStack Start SSR; a fresh instance is created per request on the server, so concurrent requests never share a language. Paraglide was not chosen: it needs a compiler step that the Lovable Vite preset does not expose.
2. **No flash of the wrong language.** Every locale bundle is imported eagerly (`import.meta.glob`), the root route resolves the language in `beforeLoad` on the server, and `<html lang>` plus the provider are rendered from it. The first HTML already carries the right text.
3. **Resolution order: profile language, then the `puntr_lang` cookie, then `Accept-Language`, then en-ZA.** The profile layer is wired in P6 (column `profiles.language` exists). The cookie is written only when a visitor picks a language, so it is a functional cookie they asked for, not tracking. No per-language URLs at launch.
4. **Only enabled languages are offered.** `src/locales/config.ts` holds `enabled`, `reviewed`, `reviewedBy` and `reviewedAt` per language. af, zu and xh are off until a native-speaker reviewer approves them (P13). Missing keys fall back to en-ZA key by key.
5. **Formatting is one house style in every language** (`src/lib/format.ts`): `money()` gives `R1 234,50`, `odds()` gives `2.10`, `pct()` gives `62%`, dates `Sat 31 Oct 2026`, times `17:30 SAST`. Money never goes through `Intl.NumberFormat` because the output differs per locale.

## Writing a screen

```tsx
const { t } = useTranslation("home");
<h1>{t("hero.title1")}</h1>
```

- Keys, not sentences. Plurals use `_one` / `_other` and a `count` option.
- Rich text uses `<Trans>` with numbered components (`<1>link</1>`).
- Route `head()` metadata uses `headT(match.context.locale, "ns")` from `src/lib/i18n/head.ts`.
- The responsible-gambling message is only ever `<RgNotice />` (`variant="compact"` for a one-liner). The helpline number is a constant, never translated.
- Proper nouns are never translated: Puntr, PuntPoints, team, competition and bookmaker names, "1X2". See `docs/i18n/glossary.md`.
- Emails take a locale: `emailT(locale)` from `src/lib/email/i18n.ts`, English fallback.

## Namespaces

`common, nav, home, predictions, match, rg, auth, consent, privacy-summary, legal-summary, support, affiliate, payments, errors` as specified, plus `howitworks, pricing, community, leaderboards, results, insights, about, comingsoon, email` for pages that have no home in that list.

Full legal pages (terms, privacy, cookies, refunds, privacy request, affiliate disclosure) stay English by design. The summaries shown elsewhere belong in `privacy-summary` and `legal-summary`.

## Pseudo-locale (development only)

`en-XA` accents every vowel and pads strings about 30%. In `bun run dev` it appears in the language switcher; or set `document.cookie = "puntr_lang=en-XA"`. Anything still in plain English is hard-coded. It is never offered in a production build.

## Checks

- `bun run i18n:check` lists keys missing per language and hard-coded text left in JSX. Warn only for now (`--strict` exits 1).
- `bun run test` runs the formatter tests and the locale resolution tests.

## Adding a language

1. Create `src/locales/<code>/` and copy the en-ZA files; translate.
2. Have a native speaker review it using `docs/i18n/glossary.md`.
3. In `src/locales/config.ts` set `enabled`, `reviewed`, `reviewedBy`, `reviewedAt` in one commit.
